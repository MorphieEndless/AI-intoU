# 服务端重构设计文档（2026-09）

这组文档是 AI-intoU 服务端重构的**单一事实源（Single Source of Truth）**。
任何 AI 会话或人类在动手改服务端代码之前，必须先读完 `02-architecture.md`，
尤其是其中的「设计铁律」一节。

## 为什么有这组文档

服务端代码由 AI 多轮生成，缺乏统一架构约束，已经出现明显的碎片化
（实锤见 `00-current-state.md` 的已知问题清单）。本组文档的目的：

1. **冻结现状**：盘点现有行为，防止重构中悄悄丢失已能用的功能。
2. **锁定决策**：把产品决策写成文字，避免每次开发重新发明一遍。
3. **提供契约**：给所有实现者（AI 或人类）一份不可违反的架构约束。

## AI 协作铁律

1. **文档先行**：任何与本文档冲突的实现，先改文档（写明理由），再改代码。
   不允许「代码先跑偏，文档没人管」。
2. **每轮 AI 会话的 prompt 必须附带** `02-architecture.md` 全文
   （至少附带「设计铁律」「目录结构」「数据模型」三节）。
3. **测试是契约**：每个里程碑先写验收测试，实现以通过测试为准。
4. **偏离要留痕**：不得不偏离设计时，在对应文档末尾「决策记录」
   追加一条 ADR（日期 / 决策 / 理由），不许静默偏离。
5. 重构期间**行为兼容优先**：Android App 与 MCP 客户端的既有协议
   不破坏，除非里程碑中明确列出变更。
