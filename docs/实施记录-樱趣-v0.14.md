# 樱趣 v0.14 实施记录 · 控制面板文案与导航重构

基准：v0.13（main @ `790b3a1`，`android/app/build.gradle.kts` versionCode 18 / 0.13.0）。
本轮成果在 `/workspace/ai-intou-v014/`。版本号 **0.14.0 / 19**。

## 改动清单

### 1 震动档位语义补全（7 / 8 / 9 档）

原先 `vibDescriptions` 只覆盖 0-6 与 10，7-9 无描述（注释写明「尚未逐档校准，不显示描述」）。
本轮按真机逐档体感补全，整套 0-10 现在齐备：

| 档 | 文案 | 依据 |
|---|---|---|
| 7 | 微颤渐强 | 先是上下颤动，随后渐强 |
| 8 | 中震×4 + 强震×1 | 四次中震之后接一次强震 |
| 9 | 快速断续 + 强震×1 | 类似 5 档断续的急促加快版，尾段紧跟一记强震 |

措辞沿用 6 档「中震×6 + 强震×2」的公式化结构，并让 9 档与 5 档「断续」形成可对照的命名关系。
注释同步改为「0-10 档全部实测校准」。

### 2 吮吸 · 自由组合 —— 模式区改为无缝分段控件

原为 2 列 × 3 行 `FilterChip` 网格，行距 8dp，垂直间距观感散。改为 **2 段 × 3 格的无缝分段控件**：

- 每排一周 1dp 圆角边框（`RoundedCornerShape(9.dp)`），格与格之间只留一条 1dp 竖分隔线（20dp 高），整排读起来是一个控件。底色 `surfaceContainerLow`，选中格填 `secondaryContainer` + `SemiBold`。
- 网格高度由 **112dp 降到 72dp**；卡片内容块间距 14dp → 10dp（模式标签 / 段列 / 数值行 / 滑条同属一组）。
- 交互与旧版逐项保持一致：点模式即按当前档位下发（0 档只切模式、不下发）、滑条松手下发、0 档视为停止。**未**恢复「应用 / 停止」按钮。

同时按真机实测定名，`suctionModes` 三处改名：`另类脉冲 → 交替脉冲`、`持续 → 持续直吸`、`节奏 A → 波浪律动`。

### 3 波形库 —— 去掉重放的二次确认

详情弹窗原先点「重放」会再弹一次「现在重放？」，确认后才执行。二次确认与 `confirmPlay` 状态一并删除，
点「重放」直接进入既有的「取最新定义 → 校验 → 交前台 Relay 执行」链路。

按钮文案保持「重放」。**未**改动重放链路本身：仍是确认时重新拉取最新定义、经校验后通过 Intent 交
`RelayService` / `CommandDispatcher` 在本机执行，切换页面不停止后台波形。

### 4 破坏性操作 —— 确认输入由「完整 Token」缩短为「末尾 20 位」

账户模式下 Token 是近 200 位的 JWT，原设计要求**手动逐字输入完整 Token**（且屏蔽粘贴、拦截批量注入），
实际不可用。改为：

- 新增 `private const val CONFIRM_TAIL_LENGTH = 20`，校验 `token.trim().takeLast(CONFIRM_TAIL_LENGTH)`。
- 上方展示区不再横向滚动铺长串，改为小卡：小字说明「当前 Token 末尾 20 位（完整 Token 共 N 位）」，大字只显示那 20 位。
- 输入框标签、错误提示、通过提示同步改为按「末尾 N 位」表述。
- **防误触机制全部保留**：屏蔽系统粘贴菜单（`LocalTextToolbar` override）、拦截批量注入（长度增量 > 1 判为粘贴）、仅逐字输入且完全匹配方可激活「确认删除」。
- 未配置 Token 时（如仅测蓝牙）退化为固定短语 `CONFIRM-DELETE-LOCAL-HISTORY`。

### 5 底栏四栏 + 波形库独立成页

- `AppScreen` 增 `PATTERNS`：`{ DASHBOARD, PATTERNS, LOGS, SETTINGS }`。
- 底栏顺序改为「玩具 · 波形库 · 日志 · 设置」，波形库居中，图标 `Icons.Outlined.Waves`。
- 「玩具」页内的 `TabRow(设备控制 / 波形库)` 二级结构随之移除：`ToyPages` 成为死代码，已删除；玩具页现在直接是设备控制面板。
- 未配置服务器时点进波形库，走新增的 `PatternLibraryPlaceholder`（说明需要服务器 + 「打开设置」按钮），不再假装空库。
- 返回键行为不变：任何非玩具页按返回都回玩具页。

### 6 版本号

`android/app/build.gradle.kts`：versionCode 18 → **19**，versionName 0.13.0 → **0.14.0**。

### 7 泄露门禁 §5 误报修正（`scripts/check-leaks.sh`）

**这是存量问题，不是本轮引入。** `repo-specific patterns` 在 main 上长期为红：
PR #3（v0.13.0）的同一检查同样是 failure。

根因是该脚本 §5「内部域名 / 隧道地址」的匹配里有一个**裸 `example` 通配**：

```bash
'example|in2\.[a-z0-9-]+\.(top|com|net)|...'
```

它把文档与代码里**推荐使用的占位符**一并命中 —— `your-server.example.com`、
README 的 `https://example.com` —— 连散文里出现的「例如 example」也照抓。

改法（保持原有防护意图，不放行任何真实地址）：

1. 裸 `example` 收紧为 `example\.[a-z]{2,}`，只认域名形态；
2. 按 **RFC 2606 保留域**放行：`example.com / .net / .org / .edu / .gov / .mil / .int`
   以及保留 TLD（`.test / .invalid / .localhost`）。这些指向不了任何主机，
   与脚本里**早已放行**的 `your-subdomain.duckdns.org` 属同一类；
   白名单里依旧没有任何真实地址（符合 `.gitleaks.toml` 头部那句「若要 CI 变绿请改文档，
   不要往 allowlist 里加真实值」）。 但 `example.<真实 TLD>`（如 `example.top`）**照拦不误** ——
   那不是占位符，是把真实域名伪装成示例形态。

**顺带修掉一处漏报**：原实现用 `grep -vE` 整行剔除占位符。若同一行里既有占位符
又有真实残留，整行会被放过。现改为「先在命中行里抹掉占位符，再复检该行」，
「占位符 + 真实残留」同行的情形也能拦下。

本地对照验证（同一棵树，仅替换脚本）：

| | 结果 |
|---|---|
| 旧脚本 | `EXIT=1`，复现 CI 红：命中 `ConnectionSettingsScreen.kt:253` 的 `your-server.example.com` 占位符 |
| 新脚本 | 六节全 `ok`，`EXIT=0` |

判定用例另测：`example.com` / `your-server.example.com` / 散文「例如 example」→ 放行；
`yingti.example.top` → 拦下；**混写行**（先 `example.com` 再 `yingti.example.top`）→ 仍拦下。

> 留给维护者的两点观察（**本次未改**，供后续决定）：
> 1. `.gitleaks.toml` 规则 4 的 `(?:[a-z0-9-]+\\.)?example\.[a-z]+` 里那个 `\\.`
>    在 TOML 字面串中不会被转义，进到正则里是「反斜杠 + 任意字符」，该可选组实际永不匹配；
>    剩下的 `example\.[a-z]+` 本身足以命中 `example.com`。本次该检查之所以是绿的，
>    是因为它只扫本 PR 的 diff，而 `example.com` 那行不在 diff 内 —— 属潜在隐患，
>    一旦后续改动碰到那一行就会转红。
> 2. 红线 R4 禁止的 `sslip.io` / `nip.io` / `xip.io` / `traefik.me`
>    目前两个扫描器都没有覆盖（脚本 §5 与 gitleaks 规则 4 都只列了 in2 / ngrok / trycloudflare / duckdns）。
>    补进去会把明文写着这些域名的 README 一并命中，需要先决定怎么表述禁令。
